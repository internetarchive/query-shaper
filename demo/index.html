Query Shaper — Demo

Each instance below enhances a plain search input with on-device AI Suggestions (Correction, Expansion, Expression). Type a natural-language query, wait a moment for Suggestions to appear, then accept one to see that instance's configured Action run. Requires Chrome with the on-device LanguageModel available — see README.md.

1. Internet Archive

Fields declared as an inline JSON schema; Format lucene; Action opensearch against a hand-built template (no published OpenSearch document for archive.org).

2. Open Library

Format lucene; Action opensearch, with the template sourced directly from Open Library's real OpenSearch description document.

3. Wayback Machine — gov collection search

The gov collection itself is fixed configuration baked into the template, never a Field the model varies. Format lucene; the {searchTerms} placeholder sits in a path segment, not a query string.

4. Ask Me Twice (REST API)

A live, GET-only JSON API — no results page to navigate to, so action="output" fills the Target and writes the constructed URL below as a clickable link (it does support CORS on its data endpoints, but this demo still doesn't fetch inline, for the same reason none of the others do — Accept produces something to act on, not a rendered result). Fields declare two endpoints: responses (list, filterable by real query parameters) and questions/{slug} (single-item lookup by a model-guessed slug, demonstrating path-parameter substitution). Format rest-api; base is the API's real root.

5. No Fields declared

Without Fields, only Correction and Expansion Suggestions are offered — no Expression.

6. Free-form text Fields

A loosely specified, human-written Fields description still produces sensible Expression Suggestions.

7. Inline JSON Fields

The more precise, structured declaration path.

8. Custom .format render function

The escape hatch for backends neither built-in preset covers — set imperatively since a render function can't be expressed as an attribute.
